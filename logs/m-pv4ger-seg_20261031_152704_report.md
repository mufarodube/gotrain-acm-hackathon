## Report for m-pv4ger-seg

**Best config (trial t10):** Unet with a resnet34 encoder, `img_size` 320 (native), `dice_weight` 0.3, 25 epochs, default lr. It scored **validation mIoU 0.9590** (foreground IoU 0.9347).

**Confirmation:** I reran the same config with `seed` 1 and got 0.9583 (best epoch 22), a drop of only 0.07 points. That is within noise, so the result holds. The same config with `dice_weight` 1 scored 0.9575 and 0.9576 on two seeds. So the gain from 25 epochs is solid, at about +0.2 points over the 15-epoch baseline of 0.9554. The gain from `dice_weight` 0.3 is marginal, at about +0.1 points and under the noise level.

**What helped**
- A longer schedule (25 epochs instead of 15) was the main gain. The curves were still rising at epoch 15.
- A lower `dice_weight` of 0.3 gave a small gain, probably because foreground is about 19% of pixels, so Dice is less important here.

**What did not help** (15-epoch trials score against the 0.9554 baseline)

| Change | Val score |
|---|---|
| DeepLabV3Plus (15 epochs) | 0.9522 |
| DeepLabV3Plus (25 epochs, dice 0.3) | 0.9536 |
| resnet50 encoder | 0.9535 |
| resnet18 encoder | 0.9530 |
| lr 1e-3 | 0.9513 |
| lr 1e-4 | 0.9541 |
| `img_size` 416 (upsampling) | 0.9533 |

**Stopping:** I stopped with 3 trials unused. The last 3 trials (t11–t13) did not beat t10, and the stop rule is 3 consecutive non-improving trials.

**What I would try next**
- Run 40 or more epochs, since the curve was still creeping up at the end.
- Try Unet++ or an FPN decoder, if the config allows them.
- Try a stronger pretrained encoder, such as a ResNeXt or EfficientNet variant.
- Average predictions over test-time flips and rotations.

Treat gaps under about 0.3 points between configs as noise on this 403-image validation set.
